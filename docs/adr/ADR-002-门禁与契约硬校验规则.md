# ADR-002：门禁与契约硬校验规则（T3）

- 状态：已接受
- 日期：2026-11-14
- 决策人：陈欣然（角色1）

## 背景

规格书 3.2 要求把描述性护栏转化为可判定的 if-else 分支；T3 验收标准要求
"AgentMessageRequest 拦截空引用；StageAdvanceRequest 拦截空人类输入"。

## 决策

统一错误码体系（`backend/gate/service.py`），所有校验失败返回 HTTP 400 + JSON `detail.code`：

| 错误码 | 触发条件 | 对应护栏 |
|---|---|---|
| E001 | 发言内容为空 | 契约校验 |
| E002 | `references` 为空 | 发言门槛（无限发散防御） |
| E003 | 引用的条目 ID 不存在 | 空引用 |
| E004 | 引用条目 EntryStatus != APPROVED | 幻觉传染防御（action=PROJECT_PAUSED） |
| E005 | 项目非 RUNNING 状态 | 状态门槛 |
| E101 | `human_prompt_input` 为空 | 人类袖手旁观防御 |
| E102 | 跨阶段推进 | 阶段状态机 |
| E103 | 项目已冻结 | 基线只读 |
| E202 | 门禁驳回未填 reason | 规格书 4.2 |

## 理由

前端 `frontend/src/api` 依据错误码做信号映射（如 E101 → 推进按钮灰显 + tooltip），
错误码一旦发布即视为契约的一部分，与 `/contracts` 同级冻结。
