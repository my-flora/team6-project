# ADR-001：技术栈选型 —— Python FastAPI 后端 + TypeScript 前端

- 状态：已接受
- 日期：2026-11-14
- 决策人：陈欣然（角色1 · 契约与门槛组长）

## 背景

第6组虚拟项目室系统需要落地 T1（数据模型/枚举）、T3（门禁与契约校验）、T10（基线冻结与变更接口）。
候选方案：Python FastAPI、Node.js/TS 全栈、Go。

## 决策

采用 **Python FastAPI + Pydantic** 实现后端服务，前端使用 **TypeScript** 手写冻结版 API client。

## 理由

1. Pydantic 模型与规格书 1.2 的实体/枚举一一映射，天然支持契约校验（T3 验收标准用 `HTTPException(400)` 即可表达）；
2. FastAPI 自动生成 OpenAPI 文档，便于 T2/T4/T5~T9 各 Owner 对照契约开发；
3. 全组均为产品/工程混合背景，Python 实现成本最低，利于 T11 全员联调。

## 后果

- 后端各服务共用 `backend/core` 枚举，禁止自定义状态值；
- 前端 `frontend/src/api` 为冻结版，字段变更必须先改 `/contracts` 并新增 ADR。
